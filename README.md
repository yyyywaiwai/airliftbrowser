# Airlift Browser

USB接続したiPad / iPhoneのアプリを、コンテナ単位で閲覧・編集・バックアップ／リストアするSwiftUI製macOSアプリ。
macOS 14以降。Xcode / Swift 6、開発者モードを有効にした端末、`pymobiledevice3`が必要です。
PythonはHomebrewの `/opt/homebrew/bin/python3` または `/usr/local/bin/python3` を自動検出します。

## 起動

```sh
git submodule update --init --recursive
make        # .app生成 (dist/Airlift Browser.app)
make open   # ビルドしてアプリを起動
```

`Package.swift` をXcodeで開いてソースを編集できます。ヘルパーの同梱と署名を含む
実行用アプリは上記スクリプトで作成してください。ローカル用アドホック署名です。
配布用のDeveloper ID署名・公証は含みません。

## アプリ管理

1. iPhone / iPadをUSB接続し、ロック解除してこのMacを信頼します。
2. サイドバーの「アプリ」で、名前・Bundle IDからアプリを選択します。
3. 「データ」「App Group」「アプリ本体」を切り替え、ダブルクリックでフォルダやファイルを開きます。
4. 「バックアップ」で、データ（キャッシュ・tmpを含む）・App Group・アプリ本体から保存対象を選びます。
5. 「バックアップ履歴」またはサイドバーの「バックアップ」から、閲覧・書き出し・リストアします。

バックアップ・リストア・読み込み／書き出し・復旧では、前面の大型シートに処理ログを表示します。
現在の領域、分割送受信のチャンク数と容量、転送速度、照合／端末内コピー／復帰／後片付け、経過時間を確認できます。
バックアップ／リストアでは、全体のプログレスバーと領域ごとの工程一覧を表示します。
全体は各工程を等しく重み付けした進捗で、所要時間の予測ではありません。
転送・検証の工程は合計バイト数で進み、接続・集計・復帰など容量を数えられない工程は実行中表示になります。
各工程は待機中・実行中・完了・スキップ・中断を区別します。
中止後もコンテナの復帰が終わるまでシートを保持し、完了・失敗後はログを読んでから閉じられます。
一時移動中にコンテナが作り直されるのを避けるため、処理中は端末で対象アプリを開かないでください。
ログの全記録は `~/Library/Application Support/Airlift Browser/Logs/` に保存し、画面には最新1,000行を表示します。

バックアップ・リストア両方のシート内の「バックアップ／リストアの内容検証」で検証を切り替えられます（初期値はオン、共通設定として保存）。
オフの場合、バックアップでは保存ファイルの再読み込み照合、
リストアでは事前のバックアップ内容照合と復元後の読み戻し照合を省略し、工程一覧・ログにスキップを記録します。
受信中のSHA-256計算はバックアップ索引用に行います。転送完了・サイズ・コンテナ復帰の確認は引き続き行います。

- ユーザーアプリ、標準アプリ、列挙可能な残存コンテナに対応します。残存コンテナの推定名は確定情報と区別します。
- 通常のDVT一覧で内部を読めないコンテナも、AirliftでMediaへ一時回収してAFCから列挙します。
  各操作後に元の場所へ戻し、移動先の実在・状態とBooks同期状態の復帰を確認します。
- アプリや関連する拡張プロセスを終了してから操作します。これはOS全体の原子的スナップショットではありません。
- ファイル／フォルダの取り出し、送信、明示的な上書き、削除、名前変更、フォルダ作成に対応します。
- テキスト、XML／バイナリplist、16進数の編集に対応します。バイナリplistは保存時もバイナリ形式です。
  16進数編集は4 KiB単位のページ表示・同じバイト数での置換です。16 MiBを超えるファイルは16進数表示を使います。
- 画像・PDFなどはQuick Lookでプレビューします。端末ファイルの編集保存時には、開いた時点のハッシュと照合します。
- アプリ本体は閲覧・保存用です。端末側でコピーとして取り出される領域は元へ上書きしません。
  AirTrafficの応答後もコピーが続く場合があるため、ルートの時刻・状態と配下のファイル一覧・サイズの
  安定を確認してから一覧表示・保存を開始します。コピー中の中止・復旧も完了を待って後片付けします。

## バックアップとリストア

保存場所は `~/Library/Application Support/Airlift Browser/Backups/` です。

- `.airliftbackup` は、`Manifest.json` と `Payload/` を含む持ち出し可能なパッケージです。
  アプリ・端末情報、日時、領域、ファイル一覧、SHA-256、取得可能な時刻・種類・リンク先を記録します。
- 端末を接続していないときも一覧・閲覧・編集できます。編集は新しい履歴として保存します。
- 一覧・履歴の右クリックで「Finderに表示」「復元」「エクスポート」「ゴミ箱に移動」を選べます。
  削除はMacのゴミ箱へ移動します。選択中のバックアップはツールバーの「削除」からも削除できます。
- `xcappdata` の `AppData/` と `AppDataInfo.plist` を読み込み・書き出しできます。
  xcappdataに書き出すのはデータ領域です。App Group・本体の保存には `.airliftbackup` を使います。
- 端末全体のFinderバックアップを作らず、選択したアプリを毎回全量保存します。
  データ・App Group・本体を選択でき、選択した領域は全量保存します。
  暗号化、一括処理、差分バックアップ、領域内の一部ファイルのみのバックアップ、Finderバックアップ形式は対象外です。
- 取得できなかった領域は「一部未取得」、途中終了した保存は「未完了」と表示します。未完了の保存は復元できません。
- リストアは「完全置換」「上書き・追加」を選択できます。App Groupは領域ごとに復元先を選びます。
- 復元先の現在のコンテナを毎回解決するため、再インストール後・別端末・別バージョン・別Bundle IDを指定できます。
  OS管理用コンテナ識別情報は復元先のものを維持します。アプリ固有のデータ形式の変換は行いません。
- 新しいアプリ管理の転送は4 MiB単位でストリーミングし、10 GB規模や4 GB超の単一ファイルを扱える構成です。
  分割ファイルや大容量ZIPを事前生成せず、同じAFC接続・ファイルハンドルで連続転送します。
  送信内容は読み戻してSHA-256を照合し、リストアではファイル集合も照合します。
- リストアでは、転送直後と復元先で重複していた読み戻しを復元先の最終照合に統合しています。
  検証オンでは照合が成功するまで、オフでは転送が成功するまで変更前の項目を保持します。
  バックアップでは受信と保存内容の照合結果を索引作成に使い、検証オフでは受信中のハッシュを使います。
- 操作状態と変更前の項目を記録します。中止時は変更を戻してコンテナを復帰し、切断・異常終了時は
  再接続後の「未完了操作を復旧」から処理できます。完了済みの別領域はロールバック対象になりません。
  記録は `~/Library/Application Support/Airlift Browser/Operations/` に保存します。

## Media・一時ファイル・Apple Pay

- 「Media」は通常 `/var/mobile/Media` に対応します。AFCで一覧・送受信・削除・名前変更を行います。
- 「一時ファイル」は `/var/tmp` を開きます。絶対パス入力による端末全体のブラウズUIは廃止しました。
- 既存のMedia／一時ファイルの転送には128 MiB制限があります。アプリ管理の新しい転送とは別の処理です。
- Finderとのドラッグ＆ドロップ、複数選択、Apple Pay券面操作、AirTraffic PoCは従来の画面から利用できます。

## 元プロジェクトとの関係

[0xjohnnydev/airlift](https://github.com/0xjohnnydev/airlift) を `airlift/` に
submoduleとしてcloneし、コミット `c684cd41ca0ded2d1ab780c15f6ead05509ce062` に固定。
`Sources/BrowserBridge/main.m` は元の `device_helper.m` をincludeして、ペアリング・
AFC接続・読み書きの関数を再利用しています。元ソースは変更していません。
上流MITライセンスはアプリにも同梱します。

上流はAirTrafficによる既知パスへの書き込みと、一時移動による読み戻しを検証するPoCです。
一般的なルートディレクトリ一覧APIではありません。GUIの「AirTraffic PoCを実行…」は
上流と同じ処理を実行します。新しいアプリ管理は上流の小さなリンク生成用アーカイブを再利用し、
コンテナの実データはPythonのAFC接続でストリーミングします。iPad対応は上流の
iPhone限定チェックをローカルビルド時にiPadへ広げたもので、実機結果を下記に記録します。
